# 설계 문서 (design)

**지금 이 컴포넌트가 어떤 모습인지**를 담는다. 컴포넌트 1개 = 파일 1개
(`{{component}}.md`, 영문 소문자 슬러그 — ADR 0003). 형식은
[`0000-template.md`](./0000-template.md).

## ADR과 무엇이 다른가

| | 설계 문서(여기) | ADR(`../adr/`) |
|---|---|---|
| 담는 것 | **지금 어떤 모습인가** | **왜 그렇게 정했는가** |
| 갱신 | 최신 상태로 **덮어쓴다** | 본문 불변, **추가만** 한다 |
| 과거 | 남기지 않는다 | 그대로 보존한다 |

설계는 계속 바뀐다. 바뀌는 것을 불변 기록(ADR)에만 두면 "현재 설계가 무엇인지" 알기 위해
ADR을 시간순으로 읽고 머릿속에서 합성해야 한다 — 하나만 놓쳐도 틀린 구현이 나온다.
그래서 **현재 모습은 여기, 근거는 ADR**로 나눈다(ADR 0006).

- 설계를 바꿀 때는 **이 문서를 덮어쓰고**, 왜 바꿨는지는 ADR로 남겨 링크한다.
- 이 문서에 "예전에는 …였다"를 적지 않는다. 그건 ADR과 git 히스토리의 몫이다.
- 코드와 어긋난 설계 문서는 없는 것보다 나쁘다. 구현이 바뀌면 같은 PR에서 함께 고친다.

## 언제 만드나

**미리 만들지 않는다.** 컴포넌트가 실제로 생겼고, 그 구조를 말로 설명해야 하는 순간에
만든다. 한 파일에 다 적히는 규모라면 아직 이르다.

새 문서를 추가하면 아래 표에 한 줄 등록한다.

| 컴포넌트 | 문서 | 한 줄 설명 |
|---|---|---|
| (없음) | — | — |

기입 예시(실제 파일이 생기면 이 형식으로 바꾼다):

```markdown
| {{컴포넌트-A}} | [server.md](./server.md) | 수집 요청을 받아 저장소에 넣는 백엔드 |
```
