# .ai — AI 에이전트 공용 작업 메모리

이 폴더는 이 저장소에서 일하는 **AI 에이전트(Claude Code, Codex)** 가 공유하는 개발 과정의
기록이다. 특정 도구에 종속되지 않으며, 배포물이 아니라 저장소에서만 보는 내부 문서다.

> 규칙은 [`AGENTS.md`](../AGENTS.md)가 단일 출처다. 이 파일은 **`.ai/` 문서들의 역할과 추가
> 절차**를 정한다.

## 문서별 역할

문서를 나누는 축은 주제가 아니라 **어떻게 갱신되는가**다. 덮어쓰는 문서와 추가만 하는 문서를
한 파일에 섞으면 둘 다 망가진다 — 최신 상태를 보려면 과거를 걷어내야 하고, 과거를 보려면
이미 덮어쓴 뒤다.

| 질문 | 문서 | 갱신 |
|---|---|---|
| 만들고 싶은 게 뭔가 | [`backlog.md`](./backlog.md) | 덮어씀 |
| 무엇을 만들기로 했고 어디까지 됐나 | [`status.md`](./status.md) | 덮어씀 |
| 지금 어떤 모습인가 | [`design/`](./design/) | 덮어씀 |
| 왜 그렇게 정했나 | [`adr/`](./adr/) | **추가만** |
| 왜 아직 안 됐나 | [`issues/`](./issues/) | 상태만 갱신 |
| 무엇을 했나 | [`work-result/`](./work-result/) | **추가만** |

- **[`backlog.md`](./backlog.md)** — 하고 싶지만 아직 범위가 아닌 것. 채택되면 `status.md`의
  구현 현황 표에 `🚧 시작 전`으로 옮기고 여기서 지운다. 채택은 소유자가 정한다.
- **[`status.md`](./status.md)** — 구현 현황. **이 문서의 구현 현황 표가 곧 범위다.**
  다른 문서는 상태를 자체 서술하지 않고 이 문서를 인용한다.
- **[`design/`](./design/)** — 지금의 설계와 인터페이스 계약. 컴포넌트 1개 = 파일 1개.
  현재 모습만 담고 덮어쓴다. "왜"는 담지 않고 ADR을 링크한다. **미리 만들지 않고**,
  컴포넌트가 실제로 생겨 구조를 설명해야 할 때 만든다.
- **[`adr/`](./adr/)** — 결정 1건 = 파일 1개. 배경·결정·결과를 남긴다.
- **[`issues/`](./issues/)** — 미해결이거나 의도적으로 미룬 것.
- **[`work-result/`](./work-result/)** — 작업 1건 = 파일 1개. PR 본문과 중복해서 쓰지 않는다
  (역할 분담은 `AGENTS.md` 11절).

그 밖의 문서가 필요해지면 이 폴더 아래에 두고 이 목록에 등록한다. 미리 만들어 두지 않는다.

## 새 문서 추가하기

1. 해당 폴더의 `0000-template.md`를 복사해 파일을 만든다.

   | 폴더 | 파일명 |
   |---|---|
   | `adr/`, `issues/` | `NNNN-slug.md` (마지막 번호 +1, 4자리 zero-pad) |
   | `work-result/` | `yyyymmdd-slug.md` |
   | `design/` | `{{component}}.md` |

   슬러그는 **영문 소문자·숫자·하이픈**만 쓴다(`AGENTS.md` 10절). 한글 제목은 파일 안의 H1과
   인덱스 표의 링크 텍스트가 담는다.

2. 머리말을 채운다. ADR·이슈·작업 결과는 `Phase` 필드를 비워두지 않는다(없으면 `해당 없음`).
3. **그 폴더의 `README.md` 인덱스 표에 한 줄 추가한다.** 템플릿 파일은 인덱스에 넣지 않는다.

빠뜨린 것은 CI가 잡는다. 올리기 전에 로컬에서 먼저 돌린다.

```bash
python3 .github/scripts/check_markdown_links.py
python3 .github/scripts/check_doc_index.py
```

## 상태 어휘

상태 값은 **아래 표에 있는 것만 쓴다.** 새 값을 만들지 않는다 — 표현하고 싶은 상태가 없으면
그 자체가 결정이므로 ADR로 남기고 이 표를 고친다. 인덱스 표의 상태는 파일 머리말의 상태와
같아야 하며, CI가 확인한다.

### `adr/` — 결정의 상태

| 값 | 뜻 | 언제 |
|---|---|---|
| `Accepted` | 확정되어 적용됨 | 기본값. 결정을 내렸고 지금 유효하다 |
| `Proposed` | 제안됨, 미확정 | 소유자 승인을 기다린다 |
| `Superseded by NNNN` | 후속 결정으로 대체됨 | 뒤집혔다. 새 ADR 번호를 함께 적는다 |
| `Deprecated` | 더 이상 유효하지 않음 | 대체 결정 없이 폐기됐다 |

### `issues/` — 이슈의 상태

| 값 | 뜻 | 언제 |
|---|---|---|
| `Open` | 미해결 | 기본값 |
| `Deferred(사유)` | 의도적으로 미룸 | 사유를 괄호 안에 적는다. 예: `Deferred(환경 제약)` |
| `Resolved` | 해결됨 | 날짜와 관련 PR/ADR을 함께 남긴다. 예: `Resolved (2026-07-31, PR #12)` |

### `status.md` — 항목의 진행

| 값 | 뜻 |
|---|---|
| `🚧 시작 전` | 범위에 넣기로 했으나 아직 손대지 않았다 |
| `🟡 진행 중` | 일부 되어 있고 TODO가 남았다 |
| `✅ 완료` | 끝났다 |

`design/`과 `work-result/`에는 상태가 없다 — 설계는 항상 현재 모습이고, 작업 결과는 끝난
기록이다.

## 결정을 뒤집을 때

새 ADR을 쓰고, 옛 ADR의 상태를 `Superseded by NNNN`으로 바꾼 뒤 새 ADR에서 링크한다.
**과거 ADR의 본문은 고쳐 쓰지 않는다** — 그 시점의 판단으로 보존한다. 머리말 필드(`상태`,
`Phase`)와 파일명은 본문이 아니므로 규약이 바뀌면 맞춰 고친다.
