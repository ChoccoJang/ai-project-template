# GitHub Actions 지침·템플릿 추가 및 PR 추적 규칙 강화

- **작업일시** : 2026-08-14
- **작업자** : Claude Code (claude/20260814-액션-지침-및-PR추적-강화)

## 작업요청사항

1. GitHub Actions 사용량이 월 한도(2,000분)의 90%에 도달했다 — Actions 관련 템플릿과 지침이
   필요하다.
2. PR 자동 추적이 일관되지 않다(하다가 안 하다가 함) — 정확하게 수행되도록 지침을 강화한다.

## 작업내용

### 목적

Actions 분(minute)은 유료 공유 예산인데 워크플로 작성 규칙이 없어, 트리거 중복·타임아웃 미지정
같은 실수가 예산을 태울 수 있었다. 실제로 기존 `docs-check.yml`은 모든 브랜치 push + PR에서
같은 검사를 두 번 실행하고 있었다. 또 PR 추적 규칙이 "주기적으로 확인한다" 수준이라 에이전트가
재예약을 빼먹으면 추적이 조용히 끊겼다.

### 변경 내용

**GitHub Actions 지침·템플릿**

- `AGENTS.md` 13절(CI / GitHub Actions Rules) 신설: 트리거 최소화(push는 기본브랜치만,
  `branches: ["**"]` 금지, `paths` 필터 필수), 모든 job에 `timeout-minutes` 필수(미지정 시
  기본 360분), `concurrency` + `cancel-in-progress` 필수, `schedule`·매트릭스는 소유자 승인
  시에만, 로컬 검증 우선, 사용량 경고 시 워크플로 확대 중단, re-run 반복 디버깅 금지.
- `.github/workflow-템플릿.yml` 신규: 위 가드레일이 미리 채워진 워크플로 시작점.
  `workflows/` 밖에 두어 그 자체로는 실행되지 않는다.
- `.github/workflows/docs-check.yml` 수정: **중복 실행 제거** — push 트리거를 `main`으로 한정
  (기존에는 브랜치 push와 PR에서 두 번 실행), `concurrency` 취소·`timeout-minutes: 5`·최소
  `permissions` 추가.

**PR 추적 규칙 강화**

- `CLAUDE.md`의 PR 추적 절을 6개 항목의 **불변 규칙**으로 재작성: ① PR을 연 턴 안에 구독+예약
  확인을 반드시 걸고 ② 깨어나면 머지/close → CI → 리뷰 → 🚀 순으로 확인 ③ PR이 열려 있는 한
  무조건 재예약 후 턴 종료("변화 없음"은 건너뛸 사유가 아님) ④ 종료 조건은 머지·close·소유자
  지시 세 가지뿐 ⑤ 구독/예약 실패 시 재시도 후 PR에 코멘트로 알림 ⑥ 새 세션이 열린 자기 PR을
  발견하면 지시 없이도 다시 건다.
- `AGENTS.md` 9절에 도구 무관 원칙 추가: "추적은 걸려 있는 상태가 기본값" — PR이 열려 있는 동안
  추적 수단이 하나도 없는 순간을 만들지 않는다.
- `README.md`·`AGENTS.md` 4절 구조도에 워크플로 템플릿 반영.

### 검증

- `python3 .github/scripts/check_markdown_links.py` → 깨진 상대 링크 0건.
- `docs-check.yml` 트리거 변경으로 이 브랜치 push에서는 CI가 돌지 않고 PR에서 1회만 실행됨
  (분 절약 동작 자체가 이 PR에서 확인된다).

## 최종정리내용

Actions 분 예산을 지키는 규칙(AGENTS 13절)과 가드레일이 채워진 워크플로 템플릿을 추가했고,
기존 docs-check의 중복 실행을 제거했다. PR 추적은 CLAUDE.md에서 6항목 불변 규칙으로 강화해
"구독+예약이 걸리지 않은 채 턴을 끝내는 것"과 "재예약 누락"을 규칙 위반으로 명시했다.
